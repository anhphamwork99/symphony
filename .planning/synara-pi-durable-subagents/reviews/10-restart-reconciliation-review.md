## 5. Risk-area dispositions

**1. Orphan advances generation WITHOUT changing attemptId — downstream correctness post-fence.**
`recordOrphanedEvent`'s aggregate UPDATE sets `observed_state='orphaned'`, `generation = input.generation + 1`, and leaves `attempt_id` unchanged (guarded WHERE `attempt_id = input.attemptId AND generation = input.generation AND observed_state NOT IN (terminal)`, `PiSubagentExecutionRepository.ts:1907-1918`). Downstream consumers keyed on (execution, attempt, generation) remain correct because every consumer re-reads the CURRENT aggregate before minting:

- Cancellation: `cancelParentTurnScope` lists via `listCancellableByParentTurn` (includes `orphaned`) and mints `cancelcmd_<exec>_<expectedAttemptId>_gen<expectedGeneration>_<thread>` from the listed record (`piSubagentCancellationCoordinator.ts:188-215`) — post-fence this mints gen N+1, the current truth; the bridge cancel is fenced on the same expected attempt/generation, and `recordCancelledAck` applies only when `input.generation === execution.generation && input.attemptId === execution.attemptId` (`:1023-1026`), so a late ack for the pre-fence generation journals without mutating. Correct.
- Outbox fence: `fenceOrSupersede` compares the CURRENT execution's attempt/generation to the entry's and supersedes when they differ (`:1596-1602`). A pre-fence outbox entry (attempt A, gen N) vs post-fence aggregate (attempt A, gen N+1) → superseded, no parent effect. Correct.
- Late terminal for the fenced generation: `recordTerminalEvent` classifies `supersededGeneration = input.generation < execution.generation` → `ignored_stale` + counted, no outbox row, no aggregate change (risk area 2 below).
- Resume (Ticket 14, future) will mint a NEW attempt — the `stale_generation` guard in `recordOrphanedEvent` (`attemptId/generation` mismatch → no fence) protects concurrent resumes in the other direction.
  One subtlety verified: generic `recordLifecycleEvent` gate is `input.generation >= currentExecution.generation` (`:469`) — after the fence, a late event at gen N is `<` N+1 → history-only (AC5's generic-late-event test proves observed stays `orphaned`). A NEW event at gen N+1 with the same attemptId would mutate the aggregate — but no production writer mints gen N+1 on attempt A (resume mints a new attempt; the fence itself is the only gen N+1 writer, through `recordOrphanedEvent`'s own transaction). Disposition: **correct; no defect.**

**2. Late terminal for pre-fence generation → `superseded_generation`, no outbox row.**
Direct source inspection (required): in `recordTerminalEvent`, the stale classification runs BEFORE any aggregate mutation, and both stale branches (`supersededAttempt || supersededGeneration`, and `alreadyTerminal`) return early after incrementing `stale_terminal_events` — the outbox INSERT exists ONLY after those returns, in the first-applicable-terminal path (`PiSubagentExecutionRepository.ts:1150-1246`; stale branches at `:1150-1176`, outbox INSERT at `:1222-1246`). Independently reproduced: AC5 unit test (late gen-1 terminal → `ignored_stale`/`superseded_generation`/count=1) and the real-Pi wallclock acceptance (the REAL child's terminal after orphan is counted, observed stays `orphaned`). Disposition: **proven; T10-AC5 holds with no stale outbox creation.**

**3. F2 join — no false exclusion of legitimately recoverable rows; T08-AC1 contract intact.**
The join `j.attempt_id = e.attempt_id AND j.generation = e.generation` (`:1554-1560`) admits a journal terminal row only when the aggregate's CURRENT attempt/generation equals the row's. This is exactly the applicability predicate of the production terminal path (`recordTerminalEvent` creates an outbox row only for the current attempt/generation; `recordCancelledAck` similarly guards). A terminal journal row that IS current but lacks an outbox row (the T08-AC1 recovery case: crash between journal commit and outbox — impossible in one transaction, but reachable from generic/legacy writers) is still recovered: the F1 test itself recovers a `recordLifecycleEvent`-written terminal (current attempt/gen 1/1, non-terminal... aggregate actually terminal in that fixture — either way the join passes because attempt/gen match) and the "recovered pending entries enter the fenced delivery path" test recovers and delivers one. Stale rows (attempt/gen no longer current) were the F2 transient-pending leak — now excluded outright. Edge considered: an aggregate that moved generation via the orphan fence while a CURRENT-attempt terminal journal row exists — cannot happen through the coordinator, because the coordinator checks journal terminal evidence BEFORE orphaning (`piSubagentRestartReconciliation.ts:313-347` precedes the owner-loss branch), so a current terminal restores rather than fences. Disposition: **correct; T08-AC1 recovery contract preserved.**

**4. Startup fork every boot — cannot crash/block boot; no-op on empty/legacy DB.**
`Effect.forkChild` around a child that (a) resolves the repository from the already-live layer, (b) `recoverCompletionOutbox` — which wraps its scan in `Effect.result` (scan failure → `{recovered:0, failures:0}`, no throw) and each entry create in `Effect.result`, and (c) `reconcilePiSubagentExecutions` — which wraps the scan, every per-execution write, and the transcript reader (`Effect.tryPromise … catch: () => null`) in `Effect.result`; settlement failures become counted `failures` + the `pi_subagent_restart_reconciliation_failed` diagnostic, never a defect escape. The fork is AFTER `startThreadRetentionJob` (server already live; history served first) and the log line fires only when there is something to report. Empty DB → `listNonTerminalExecutions` returns `[]` → no outcomes → no log. Legacy DB (no Pi tables) — tables are created by the migration set at layer boot, so the scan is a valid query returning zero rows. The only residual risk would be a defect in `Effect.forkChild` itself (framework), out of scope. Disposition: **no boot-blocking or boot-crashing path.**

**5. `recordOrphanedEvent` already-orphaned idempotence.**
Two layers: (a) deterministic eventId `orphan_<exec>_<attempt>_gen<gen>` + sequence 50 → `lookupJournalEvent` dedup returns `already_applied` before any write (the journal's `UNIQUE(execution_id, attempt_id, generation, sequence)` constraint from migration 100 is the durable backstop; the `Effect.catch` re-check replays the dedup answer on a raced insert); (b) the aggregate-side `observed_state === 'orphaned'` early return (same attempt/generation — the stale_generation guard has already excluded a different attempt/gen) → no second UPDATE, no generation advance. The coordinator then reports `orphaned` with `settled.execution.generation` — the already-fenced generation (N+1), never advancing again. Independently reproduced: AC1 test's second pass (one orphan journal row; generation unchanged; outcome generation equals the settled one). Disposition: **proven; no unbounded generation drift.**
